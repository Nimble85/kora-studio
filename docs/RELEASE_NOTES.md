# Release notes — майстер-класи (candidate)

Цей реліз готує KORA Studio до запису продажів майстер-класів і планування зустрічей. Дату проведення, вибрані свічки, Instagram клієнта, передплату та коментар можна змінювати в записі продажу. Бронювання видно у згортаному календарі «Ще», а за три дні до зустрічі — у нагадуванні на «Головній». Каталог поповнено звичайним кокосом і цінами МК. Продажі згруповано за роком і місяцем, а меню плюсика має чотири швидкі дії.

## Перед оновленням

- Зробіть резервну копію даних Supabase або браузера, якщо вони вже використовуються. Локальні записи зберігаються лише на поточному пристрої.
- Для наявної бази Supabase виконайте `supabase/migrations/20260921_workshops.sql` **до** розгортання нової версії. Скрипт додає чотири поля продажу та 20 позицій каталогу без перезапису змінених цін. Виконання тільки `ALTER TABLE` залишить каталог без нових товарів. Детальні перевірки наведено в `docs/SUPABASE_MIGRATION.md`. Для нової бази використовуйте `supabase/schema.sql`, потім `supabase/seed-products.sql`.
- Пройдіть `docs/RELEASE_CHECKLIST.md` у середовищі, де відбудеться запуск. Коміт і пуш не застосовують міграцію та не розгортають застосунок.

## Перевірено в робочій копії

- `next build` завершується успішно.
- `npm run lint` завершується без помилок, але показує попередження щодо невикористаних змінних і залежностей React hooks, які залишилися в чинному екрані.
- Сценарії після входу на мобільному екрані та Supabase міграцію потрібно перевірити в цільовому середовищі за чеклістом.

## Відомі обмеження

- Виручка від МК обчислюється за повною ціною продажу, навіть якщо внесено лише передплату. Залишок показується окремо; подальші платежі окремо не обліковуються.
- Календар створюється з продажів МК; окремих подій без продажу немає. Нагадування показується в застосунку, без push або email сповіщень.
- Поточна модель авторизації та політики Supabase не розраховані на відкритий багатокористувацький доступ. Історична собівартість з рецептів є оцінкою за поточними цінами матеріалів.
